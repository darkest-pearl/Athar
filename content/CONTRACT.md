# Portable content contract (schema 1)

The bundled pack and SAF imports use this same development-preview contract. Publication adds human editorial checks; JSON review metadata records a claim and does not authenticate an approver.

- Root: object with schemaVersion exactly integer 1, positive integer contentVersion, nonblank language, boolean developmentOnly, course object, and nonempty permissions, recordings, segments, concepts, lessons arrays.
- Each entity has a stable ID matching `[a-z][a-z0-9-]{0,63}`. IDs are unique within their own collection. Question IDs are unique within a lesson, so persistence identifies a question by (lesson ID, question ID, version).
- Course requires ID and nonblank title. Permission status is authorized, pending, or revoked. Recordings require relativePath, positive durationMs, and an authorized permissionRef. Optional recording `title` is nonblank. Optional lowercase hex `sha256` and positive integer `bytes` must be supplied together; the player checks both against the entire locally selected file off the UI thread before using it as an answer source. Segments require a known recordingId and integer source start/end milliseconds with `0 <= start < end <= duration`.
- Lessons require positive integer version, nonblank title/language, state draft/in-review/approved/published, known segmentRef, authorized permissionRef, and nonempty questions.
- Questions require positive integer version, known conceptId, nonblank prompt/explanation, 2–6 nonblank distinct choices, integer correctIndex within choices, and a sourceRef. A development fixture may use `kind: fixture-text` with passage `notes` (the lesson's nonblank notes) or `interface-contract` (a fixed neutral app-control passage). A recording source uses `kind: recording-passage` (the legacy omitted kind remains accepted), a known segment, a positive content version, and an original-file start/end range fully inside that segment. The question passage may use another segment or recording than the lesson audio.
- Null and booleans never stand in for integers. Optional notes, reviews, and speaker may be omitted; if reviews are supplied for publication they must form a list of dated review records.
- Publication rejects developmentOnly packs, unreviewed segment boundaries, lessons outside approved/published, absent current-version language/religious review records, and questions without versioned source passages inside the referenced segment.
- Runtime import additionally caps byte size and collection counts before activation. It rejects the entire candidate on any error, leaving the last working pack active. Stable IDs and versions must remain immutable; corrected teaching text requires a new version.

The Python validator is the authoring gate. Android implements the same required-field and reference rules independently; positive and negative fixtures must be exercised on both paths before release.

Runtime limits: 256 KiB total; at most 100 permissions, 100 recordings, 500 segments, 500 concepts, 100 lessons, 20 questions per lesson, 1,000 total questions, 6 choices per question, and 4,096 characters per required text field. A recording relativePath cannot be absolute or contain `..` or backslashes. Optional `prerequisiteConceptIds` is an array of at most 20 distinct, known concept IDs. A `fixture-text` sourceRef must name its own lesson, positive contentVersion, and nonblank passage. A segment sourceRef must identify a known segment and valid passage interval.

Content versions apply to the whole course pack; lesson and question versions identify immutable learning material within it. The local importer keeps fingerprints for every accepted pack, lesson/version, question/version, recording ID, and segment ID, scoped by course. A changed pack at an accepted contentVersion or changed material at an accepted immutable identity is rejected even after switching courses. A new pack version may add a new lesson or question version; recording or segment changes require new IDs. An exact previously accepted pack can be activated again. One course is active at a time, and switching courses preserves scoped local progress. Old completion and answer events retain their historical version. JSON review records are editorial workflow metadata, not cryptographic evidence of human approval.
