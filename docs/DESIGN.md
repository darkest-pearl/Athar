# Guided learning experience · milestone 3

The bounded [Duolingo interaction study](research/duolingo-experience-study.md) and [Athar learning interaction specification](design/athar-learning-experience.md) now define the evidence labels, state transitions, persistence, and first-unit acceptance checks for this direction.

Athar keeps the Garden identity and native Compose controls. The first screen names the active course, shows the next lesson and version-matched course progress, gives one Start/Continue action, and shows today's saved participation and short due review. The Path tab is an ordered vertical route grouped into content-authored units. A selected node expands to title, objective, audio duration when known, prerequisite status, and Start/Continue/Practice. Completed, current, upcoming, and due-review nodes have distinct shape, text, and color; color alone never explains state. The unit and course bars count only current-version lesson completions. Due counts use the existing bounded review batch. A bookmark is a return marker, not course completion.

The lesson route is **Objective → Listen → Takeaway → Practice → Completion**. The header names the stage and shows a five-step progress indicator. Objective introduces the supplied lesson purpose; Listen holds the reusable seekable player and a deliberate Continue action; Takeaway shows supplied notes; Practice retains short choice checks, saved explanations, and the exact answer source. Seeking or skipping audio cannot advance or credit a lesson. Back moves to the previous stage or Path, and Exit leaves a recoverable stage. Continue Study restores the exact durable quiz/review session. A Room stage row (schema v7) stores pre-quiz position by course, lesson, and version; existing completion/answer/review/study rows survive migration unchanged. A completed lesson can be opened for repeat practice without rewriting the first completion.

Visual tokens: warm ivory background `#FAF7EF`, white-ivory surface `#FFFCF5`, dark green ink `#182E27`, primary green `#236247`, soft green container `#E4EBDD`, pale green track `#EEF3E9`, restrained amber `#B4792C` for a milestone accent, and error red reserved for actual errors. Serif headings create a calm identity; body uses platform script fallback until reviewed Tigrinya typography is supplied. Base body is 18sp/28sp, stage/node labels at least 14sp, headings scale without a fixed text box. Spacing uses 4/8dp increments, 24dp phone gutters, 16/24dp card gaps, 48dp minimum tap areas, and 56dp primary actions. A 640dp reading width and scrollable content support large/landscape screens. Bottom navigation and stage actions respect system insets.

The path uses a continuous connector, generous round nodes, compact labels, and an expandable detail card rather than a flat stack of lesson panels. Current is filled green, completed has a check and a pale surface, upcoming is outlined with an order number, and Review is a distinct rounded rectangle with its due count. Unit headers show objective and saved completion fraction. Today uses a large next-step card, a small daily-goal/streak row, and a clear due-review card. Progress shows participation milestones derived from saved completions and study days; it never scores religious understanding or piety. Completion feedback celebrates the saved lesson and points to the next real step.

States to finish: initial Room loading, empty/invalid pack, missing or changed material, pending session resume, source unavailable or wrong local file, save error with retry, answered/assisted/incorrect feedback, finished unit, no reviews due, and all lessons complete. Motion is limited to brief stage/card and feedback appearance (about 150–220ms) and a progress fill that follows Android animator scale; static states carry the same meaning when animation scale is zero. No autoplay or reward sound. Player thumb drag has an accessible slider action and adjacent back/forward buttons; its range is the active playable clip, never a claim of learning completion.

Design references: [Duolingo's guided path](https://blog.duolingo.com/new-duolingo-home-screen-design/) motivates small ordered units and integrated practice; [its review guidance](https://blog.duolingo.com/how-to-review-lessons-on-duolingo/) supports easy return to completed material. Athar uses its own content and identity. The installed UI UX Pro Max search emphasized 48dp touch targets, semantic names, visible step indicators, and reduced motion. Its web-oriented clay/indigo palette and current-library claims were not adopted for this pinned native app.

# Provisional design system · historical prototype direction
Recommended: Garden. Warm ivory #FAF7EF, dark green ink #182E27, green action #236247, soft green panels #E4EBDD. Spacious reading and restrained accents fit audio-led study and older readers. Serif English titles introduce warmth; body uses native fallback. Typography is provisional until Ethiopic text review.

Alternative: Editorial. Lavender-white #F5F2FF, cobalt action #2848A0, yellow panels #FFD66E. Stronger contrast and magazine hierarchy are more energetic. One component tree and shared semantics; Settings changes tokens. Six Compose previews cover the three requested screens. Actual emulator captures are in evidence/ when available.

Spacing: 4/8dp grid, 24dp page gutters and panel padding, 16/24dp section gaps. Buttons at least 48dp, primary action 56dp; wrapping labels, vertical scroll, system inset clearance. Body 18sp / 28sp, scalable. Feedback uses text as well as color. Native Button selection/disabled semantics. Primary actions stay within content; bottom navigation reserves space.

Milestone 2 polish: Today puts the next action ahead of the compact study-day card; due practice precedes it when present. Four persistent text destinations have a selected surface and semantics, with Lesson/Quiz/Done mapped to Learn. Submitted answers become readable static cards labeled as correct or selected, while saving disables active controls. Lesson audio keeps Play, Replay, and local selection in view and folds technical identity/source switches into an expandable control. Long-form content is capped to a readable 640dp measure on wide screens; a short viewport remains scrollable. Actual emulator evidence and constraints are in `evidence/milestone2-polish.md`.

States: empty progress; development labels; disabled submission while saving; inline storage/media error; missing audio can use bundled fixture or document picker. Offline is the baseline; no network permission.

Motion: native press feedback plus a short feedback-panel fade in the second milestone. Compose follows the system animator-duration scale, including zero for reduced motion. No sound effects or autoplay; reduced motion never blocks an action.

Scripts: Ethiopic alphabet and Arabic alphabet appear only in a labeled technical test. They are not Tigrinya translations or religious passages. Arabic has explicit RTL text direction/right alignment. System fallback glyph rendering can be inspected, but real reviewed Tigrinya labels and native reading comfort remain unverified. Adopt an Ethiopic font only after glyph and licensing checks.

Tools: UI UX Pro Max CLI 2.15.0 installed project-locally under .agents/skills/ui-ux-pro-max. Read SKILL.md and used search.py design-system plus jetpack-compose accessibility/state query. Selected native semantics and 48dp targets; rejected its web landing-page/testimonial suggestion as unsuitable here. Not using its version claims as dependency authority. Impeccable not installed; official instructions inspected, browser detector is not native Android evidence.

Official setup references: https://github.com/nextlevelbuilder/ui-ux-pro-max-skill and https://github.com/pbakaus/impeccable. Installed skill files stay local and ignored, preserving them without adding the installer’s unrelated skill bundles to the application repository. Reinstall with npx --yes ui-ux-pro-max-cli@2.15.0 init --ai codex; no global skill files changed.
